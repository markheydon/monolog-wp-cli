# Documentation Review Checklist

Before considering documentation complete, verify the following:

- The document type matches the reader's goal and the shape described in [diataxis.md](diataxis.md).
- The target audience is clear from the opening section.
- Terminology matches the project's existing files and codebase.
- The content states what is in scope and avoids implying unsupported behaviour.
- Examples, commands, and file paths are consistent with the repository.
- The writing is concise and avoids generic filler.
- The destination file is appropriate for the content (see [document-placement.md](document-placement.md)).
- Links point to the right local files, the documentation site URL, or external references.
- `website/content/` pages: YAML front matter present; no documentation framework names in body prose; `weight` sensible for sidebar order.
- `README.md`: badges and requirements match [readme-packagist.md](readme-packagist.md) and `docs/readme-and-badges.md`.
